# Ghita Store — الباك اند

باك اند كامل لمتجر Ghita Store مبني بـ Node.js + Express + SQLite، وفيه:

- **إدارة المنتجات**: عرض / إضافة / تعديل / حذف / رفع صور (محمي بتسجيل دخول الأدمن).
- **إدارة الطلبات**: العميل يبعت طلبه، السيرفر يتحقق من السعر والمخزون فعليًا (مش بيصدّق كلام الفرونت اند)، وبيولّد رابط واتساب جاهز.
- **تسجيل دخول الأدمن**: بـ JWT، صالح 7 أيام.
- **مساعد ذكاء اصطناعي (Google Gemini — Interactions API، موديل `gemini-3.8-flash` مع أداة بحث جوجل)**: بيرد على استفسارات العملاء عن المنتجات والتوصيل، ولو الرسالة فيها كلمات بتدل على شكوى أو حاجة محتاجة تدخل بشري، بيقترح فتح واتساب مع صاحب المتجر تلقائيًا.
- حماية أساسية: Helmet، CORS قابل للتخصيص، Rate limiting على الطلبات والشات وتسجيل الدخول.

## التشغيل محليًا

```bash
cd backend
npm install
cp .env.example .env
# افتح .env واملأ:
#   ADMIN_USERNAME / ADMIN_PASSWORD -> بيانات دخولك كأدمن
#   JWT_SECRET                      -> أي نص عشوائي طويل
#   GOOGLE_API_KEY                  -> مفتاح Gemini بتاعك من https://aistudio.google.com/apikey
#   WHATSAPP_NUMBER                 -> رقمك بالصيغة الدولية بدون +
npm start
```

السيرفر هيشتغل على `http://localhost:4000` (أو أي بورت تحدده في `PORT`).

## أهم الـ Endpoints

| Method | المسار | الوصف | محمي؟ |
|---|---|---|---|
| GET | `/api/health` | فحص إن السيرفر شغال | لا |
| GET | `/api/products` | كل المنتجات (فلترة بـ `?category=` و `?search=`) | لا |
| GET | `/api/products/:id` | منتج واحد | لا |
| POST | `/api/products` | إضافة منتج | أدمن |
| PUT | `/api/products/:id` | تعديل منتج | أدمن |
| DELETE | `/api/products/:id` | حذف منتج | أدمن |
| POST | `/api/products/:id/images` | رفع صور (form-data, حقل `images`) | أدمن |
| POST | `/api/orders` | إرسال طلب جديد | لا |
| GET | `/api/orders` | كل الطلبات | أدمن |
| PATCH | `/api/orders/:id` | تحديث حالة الطلب | أدمن |
| POST | `/api/auth/login` | تسجيل دخول الأدمن، بيرجع `token` | لا |
| POST | `/api/chat` | إرسال رسالة للمساعد الذكي | لا |

تسجيل الدخول: ابعت `{ "username": "...", "password": "..." }` لـ `/api/auth/login`، وهترجع `token`. بعدين ابعته في كل طلب محمي كـ:
`Authorization: Bearer <token>`

## ربط الفرونت اند (ملف store.html)

في أول ملف `store.html` فيه سطر:

```js
const API_BASE_URL = "";
```

لو رفعت الباك اند على سيرفر منفصل (مثلاً Render أو Railway)، غيّر السطر ده لرابط السيرفر:

```js
const API_BASE_URL = "https://your-backend-domain.com";
```

المتجر دلوقتي بيستخدم الباك اند في **المساعد الذكي** (`/api/chat`) وفي **إرسال الطلبات** (`/api/orders`): لما `API_BASE_URL` يتضبط، السيرفر هو اللي بيتحقق من الأسعار والمخزون وبيدّي رقم الطلب. ولو السيرفر مش متاح، المتجر بيكمّل محليًا ويبعت الطلب عبر واتساب عادي. المنتجات ولوحة الأدمن لسه شغالين محليًا في المتصفح.

> مهم: لازم `ALLOWED_ORIGINS` يكون فيه دومين موقعك (مثلاً `https://ahmedosamageta.github.io`) بدل `*` في الإنتاج. وقائمة القرى في `src/config.js` لازم تطابق `VILLAGES` في `store.html`.

## تسجيل الدخول بحساب Google (في الفرونت اند)

أيقونة 👤 في أعلى الموقع بتفتح شاشة بروفايل فيها زرار "Sign in with Google" فقط (بدون إيميل/باسورد). عشان يشتغل:

1. روح لـ [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials).
2. اعمل **OAuth Client ID** من نوع **Web application**.
3. ضيف دومين موقعك (وكمان `http://localhost` للتجربة) في **Authorized JavaScript origins**.
4. انسخ الـ **Client ID** وحطه في أول ملف `store.html`:
   ```js
   const GOOGLE_CLIENT_ID = "xxxxxxxxxx.apps.googleusercontent.com";
   ```

التسجيل بيتم بالكامل في المتصفح عن طريق مكتبة Google Identity Services، وبيرجع اسم وإيميل وصورة حساب العميل يتعرضوا في شاشة البروفايل.

## النشر (Deployment)

يشتغل على أي استضافة بتدعم Node.js (Render, Railway, VPS عادي...). خطوات عامة:

1. ارفع مجلد `backend` كامل (من غير `node_modules` و `.env`).
2. `npm install` على السيرفر.
3. ضيف متغيرات البيئة (نفس اللي في `.env.example`) من لوحة تحكم الاستضافة.
4. شغّل `npm start`.
5. تأكد إن مجلد `data/` (قاعدة البيانات) و `uploads/` عندهم صلاحية كتابة، ومفضّل يكونوا على تخزين دائم (Persistent Disk) عشان البيانات متضيعش عند كل إعادة نشر.

## أهم الإصلاحات في النسخة دي

- **الطلبات**: رفض الكميات السالبة/العشرية (كانت بتزوّد المخزون وتنقص الإجمالي)، دمج المنتج المكرر قبل فحص المخزون، تنفيذ الطلب كله داخل transaction واحدة، تقريب الأسعار (`349.99 × 3`)، التحقق من الاسم والهاتف والقرية والعنوان، وإلغاء الطلب بيرجّع المخزون.
- **الصور**: الامتداد بيتحدد من نوع الصورة (بدل اسم الملف — كانت ثغرة رفع `.html`)، حذف الصور عند حذف المنتج أو فشل الرفع، وأخطاء multer بترجع 400 بدل 500.
- **المنتجات**: التحقق من السعر والكمية والتقييم (كان ممكن يتخزن `NaN`)، التأكد من وجود التصنيف، وescape لعلامات `%` و`_` في البحث.
- **الشات**: الكتالوج بيتقرا من قاعدة البيانات بدل ما يجي من الفرونت اند (كان ممكن يتلاعب بالأسعار)، حد أقصى لطول الرسالة، timeout للطلب لجوجل، تقليل `max_output_tokens`، ومطابقة كلمات التصعيد بعد توحيد الحروف العربية.
- **الأمان**: مقارنة آمنة لبيانات الأدمن، تثبيت خوارزمية JWT، `trust proxy` عشان rate-limit يشتغل خلف الاستضافة، فحص `.env` عند التشغيل، تحديث multer لـ 2.x.
- **ملاحظة**: لا تحط ملف `.env` الحقيقي في أي أرشيف أو GitHub. غيّر `GOOGLE_API_KEY` وباسورد الأدمن و`JWT_SECRET` لو الملف اتشارك قبل كده.
